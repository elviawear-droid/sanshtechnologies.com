B360

An AI analytics platform where business teams question their own data in plain English. We designed and built it, from the model gateway to an agent that investigates open questions and writes the brief.

B360

The problem

Business teams keep their data in spreadsheets, SQL databases, Snowflake, Salesforce and Tableau, but every question still waits for an analyst. B360 set out to let anyone ask in plain English and get an answer they can trust: the right numbers, from live data, with the working shown.

Trust was the hard part. A language model answering from memory will invent numbers, no single model suits every question, and company data comes with rules about who may see what.

The approach

We built the AI layer around two rules. Every model call goes through one gateway, so it is routed, retried, logged and traced the same way. Every data access goes through one governed query function, so the model writes the query but the platform runs it, on live data, within what that user is allowed to see.

The models never answer from memory. They get structured context instead (a profile of each table, the business context an admin writes, and the conversation so far), and every number on screen comes from a query the platform ran. There is no vector store: the live data is the source of truth.

One question, end to end

  1. 01RouteA fast router model reads the question and a profile of the data, and picks which model should answer. If routing fails, the question still goes through.
  2. 02Write the queryThe chosen model gets the table profiles, the business context and the SQL rules for this database, and returns its reasoning and code.
  3. 03Run on live dataThe code calls query_db, so the platform runs the SQL on the live database, inside the user’s access.
  4. 04Correct and retryIf the code fails, the error goes back to the model as a correction. It retries, then moves up to a stronger model.
  5. 05ExplainA second call writes the summary, key findings and limitations. A third suggests the next questions to ask.

Analyze: an agent for open questions

Some questions have no single answer, like “what changed this year, and what should we do about it?”. Analyze runs a staged investigation and ends in an executive brief.

  1. 01Map the metricsOne model drafts a catalogue of the metrics in the data and a second model reviews it.
  2. 02Scan and rankIt scans what moved and ranks up to five findings by business impact, urgency, strategic fit, confidence and how far they can be investigated.
  3. 03Investigate with toolsIt drills into each finding with exactly four tools: measure a metric, list what sits behind a change, check data quality, and trend a metric over time. The platform checks every argument and runs every query.
  4. 04Get a second opinionA validator from a different model family reviews each finding. Plain code checks can only lower its verdict, and weak findings go back for another pass.
  5. 05Write the briefAn executive summary, headline KPIs, findings with their evidence and an action plan, ready as a PDF. Each run is capped at 70 tool calls and 60 model calls.

What we built

What business teams use

Chat and dashboards

  • Plain-English questions on uploaded files or live data connections
  • Answers with tables, charts and the code that produced them
  • AI-generated interactive dashboards with KPI cards, charts, tables and filters, test-run before they render
  • Suggested follow-up questions after every answer
  • Thumbs up and down feedback, scored against the answer’s trace
  • Analyze reports with findings, evidence and an action plan, as a PDF

How the AI is run

Model gateway

  • Gemini, GPT, Claude and other models through one API
  • A router model that picks the model for each question, with fallbacks so routing never blocks an answer
  • Retries with backoff, then a fallback model, with the log showing which model actually answered
  • Every call traced in Langfuse, with its model, tokens and cost
  • Versioned prompts: production only serves a version someone promoted
  • Evaluation datasets for routing, analysis, dashboards and summaries

What keeps it safe

Data and governance

  • CSV, Excel, PostgreSQL, MySQL, SQL Server, Oracle, Redshift, Microsoft Fabric, Snowflake, Salesforce and Tableau
  • Roles per organisation, and nobody can grant a role above their own
  • Users only see the connections they are granted
  • Admins choose, column by column, what the AI may see
  • Masked columns reach the model only as tokens, and turn back into real values when the query runs
  • Encrypted credentials, and sign-in with Google, Microsoft or a one-time email code

In the product

How we run it

Prompts ship like code
Every prompt is versioned in Langfuse. A new version never goes live by itself: production serves only the version someone promoted, and new versions can be tried against scored real examples first.
Every answer can be traced
Each question is one trace: the router, the analysis, the summary and the suggestions, with scores for whether the generated code ran and whether the user found it useful.
Numbers come from code
Figures are computed by queries the platform runs, and in Analyze rates are recomputed from their parts in code rather than taken from a model’s text.
A model never checks itself
The reviewer is always from a different model family than the analyst. No combination of settings can make a model review its own work.

The outcome

Business teams question their own data in plain English and get answers built from live queries, with the code, the reasoning and a trace behind every number.

Open questions get a full investigation, checked by a second model, that ends in a brief with an action plan, within a fixed budget.

We keep extending it. Next is Tableau through Tableau’s own MCP server, so teams can question their dashboards’ data the same way.
